Daily News Update Portal
Project Owner: Kanha Tyagi
Primary Maintainer: Kanha Tyagi

Project Status
- Production-grade full-stack app is implemented using:
  - Backend: Node.js + Express + TypeScript
  - Frontend: React + Vite + Tailwind
  - Database: PostgreSQL
  - ORM: Drizzle ORM
  - Scheduler: node-cron (every 5 hours)
  - Auth: Session-based auth with Passport Local

Current Modules
1) Authentication and User Management
- Register/login/logout/me APIs
- Role support: normal user or admin-request user
- Admin approval workflow:
  - requested admin users are created as pending/inactive
  - existing admins can approve/reject requests
- User lifecycle fields:
  - is_admin
  - is_active
  - is_deleted (soft delete semantics for rejected admin requests)
  - admin_status (pending/approved/rejected)
- Reusable credentials for deleted users:
  - partial unique indexes enforce username/email uniqueness only where is_deleted=false

2) News Ingestion and Scraping
- Multi-source RSS ingestion by category
- Per-article image extraction:
  - RSS image fields first
  - article page OG/Twitter/JSON-LD image fallback
- Richer article text extraction from source page paragraph content
- Duplicate prevention by source_url
- Daily relevance filter:
  - ingestion restricted to current UTC publish date for cron accuracy

3) News Management (Admin)
- Single article delete
- Manual fetch trigger
- Manual scrape trigger
- Bulk delete by category
- Bulk delete by date (YYYY-MM-DD)

4) Admin Requests Module
- View pending admin requests
- Approve/reject request
- Email notification on decision (SMTP-configured environments)

5) Public News Portal
- Latest feed
- Category filtering
- Search
- Pagination
- News detail page with richer readable content and article image

Database Schema (current)
User table
- id (UUID)
- username
- email
- password
- is_admin (boolean)
- is_active (boolean)
- is_deleted (boolean)
- admin_status (text: pending/approved/rejected)
- created_at
- partial unique indexes:
  - users_username_active_uniq (username where is_deleted=false)
  - users_email_active_uniq (email where is_deleted=false)

News table
- id (UUID)
- title
- description
- content
- image_url
- source_name
- source_url (unique)
- category
- published_at
- created_at

Session table
- sid
- sess
- expire

API Endpoints (current)
Auth
- POST /api/auth/register
- POST /api/auth/login
- POST /api/auth/logout
- GET /api/auth/me

News
- GET /api/news
- GET /api/news/:id
- DELETE /api/news/:id (admin)
- POST /api/news/fetch (admin)
- POST /api/news/delete/category (admin)
- POST /api/news/delete/date (admin)

Admin
- POST /api/admin/scrape (admin)
- GET /api/admin/requests/pending (admin)
- POST /api/admin/requests/:id/approve (admin)
- POST /api/admin/requests/:id/reject (admin)

Background Jobs
- Cron schedule: every 5 hours
- Scope: fetch current-date published items from configured sources

Environment Variables
Required
- DATABASE_URL
- SESSION_SECRET
- PORT

Optional (email notifications)
- SMTP_HOST
- SMTP_PORT
- SMTP_USER
- SMTP_PASS
- SMTP_FROM

Runbook
1) npm install
2) cp .env.example .env
3) npm run db:up (optional, if using Docker DB)
4) npm run db:push
5) npm run dev

Notes
- Migrations are applied via Drizzle push command: npm run db:push
- Drizzle config: drizzle.config.ts
- Schema source: shared/schema.ts
